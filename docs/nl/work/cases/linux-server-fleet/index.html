01 · Het probleem

De servers waren nauwelijks ooit gepatcht en niemand beheerde ze. Elke server was anders ingericht en draaide zijn eigen mix van software, dus er was geen eenduidige manier om ze te onderhouden.

02 · De aanpak
  1. Elke server onder beheer gebracht, met tooling die per server is gekozen in plaats van één opzet voor alles.
  2. Patchen op volgorde van urgentie: kritieke beveiligingsupdates worden binnen enkele uren na verschijnen doorgevoerd.
  3. Patchrondes zo gepland dat de downtime hooguit een paar minuten is.
  4. Eén centraal overzicht van logs en metrics van alle servers in Elasticsearch en Kibana, met monitoring en alerting in Zabbix.
  5. Hardening en inbraakdetectie, zodat een aanvaller minder kan bereiken.
