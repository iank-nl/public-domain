01 · The problem

In October 2026, PHP disclosed two critical remote code execution flaws in the interpreter itself, known together as PHP2Shell. Exploitation in the wild was reported from the day of release. More than 100 PHP sites were potentially exposed, and a few critical systems could not be taken offline.

02 · The approach
  1. Identified which PHP version each site ran, and how PHP was run.
  2. Patched in order of risk: internet-facing first, the riskiest setups first, sensitive data before brochure sites.
  3. Checked that the fix was active in the running PHP process, not just installed on disk.
  4. Gave site owners an honest choice to go offline until patched.
  5. Monitored the critical systems that had to stay up with custom scripts that parse the logs and pass them to AI agents for review, with a person deciding on every action.
  6. Afterwards, moved several sites to a PHP version that still receives security fixes, and gave the client a clear list of remaining actions.

Every site was patched or safely closed off within an hour of the fix becoming available, and none was compromised. Several sites now run a supported PHP version, so the next flaw like this will have an official patch.
